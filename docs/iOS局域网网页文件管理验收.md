# iOS 局域网网页文件管理验收

本清单对应 2026-11-13 的当前实现。入口为游戏库左上角三个点 →「打开 MeloNX 文件夹」下方的「局域网网页文件管理」→「启动服务」→ `http://IP:端口` 地址。服务启动后，同局域网设备可直接管理 MeloNX 的 Documents，无需登录。

## 构建交付

- NanoHTTP 使用 `src/MeloNX/Dependencies/NanoHTTP` 本地 Swift Package，以固定上游 revision 为基础，包含磁盘请求体扩展；不能改回未包含扩展的远程包。
- BSD 原文保留在依赖目录，并复制到 `src/MeloNX/MeloNX/Resources/ThirdParty/NanoHTTP-LICENSE.txt`。Xcode 同步目录应把该 `.txt` 文件收入 App 资源；构建后检查 IPA 中实际存在此文件。
- `Info.plist` 和 Debug/Release 的 `INFOPLIST_KEY_NSLocalNetworkUsageDescription` 使用同一用途说明。服务不使用后台模式伪装长期运行。
- Codemagic 构建日志应保留 Swift 编译、存储测试与 HTTP 测试结果。产物可安装后再按下表逐项测试。

## 功能与安全行为

| 操作 | 预期结果 |
| --- | --- |
| 首次启动服务并允许局域网权限 | 显示 `http://IP:端口`；同 Wi-Fi 浏览器直接打开并读取根目录，无需登录 |
| 拒绝权限、断开 Wi-Fi、端口不可用 | 明确失败信息；不显示虚假的运行状态 |
| 复制地址、关闭地址页、再次打开 | 地址不丢失，复制的地址可直接访问当前服务 |
| 新浏览器或无痕窗口打开当前地址 | 无需预先建立会话即可浏览 Documents、下载文件并执行文件管理操作；删除及覆盖仍按操作流程确认 |
| 打开目录、刷新、新建文件夹 | 路径与列表一致；同名文件夹明确冲突；无结果不能静默成功 |
| 预览白名单文本/图片 | 浏览器可打开；上传 HTML/SVG 不作为同源可执行页面运行 |
| 文件上传、文件夹上传 | 正确保留相对路径；同名文件先选择覆盖/跳过；空目录按下述边界处理 |
| 删除文件/目录 | 先显示不可恢复警告及递归统计；取消后内容不变；直接绕过确认接口不能删除 |
| 确认后修改目标、重用/过期 confirmationToken | 拒绝操作并要求重新确认；confirmationToken 也绑定移动的冲突策略 |
| 移动文件、替换文件 | 成功后源消失；冲突按明确策略处理 |
| 合并目录 | 递归保留目标的其他项目，覆盖同名文件；正常错误尝试回滚，回滚未完成必须显式提示 |
| 整目录替换 | 原目录整体替换；失败时恢复原目录，恢复/清理失败保留并提示恢复目录 |
| 目标是源的子目录，或源是目标的子目录 | 拒绝移动，避免源路径随祖先重命名而失效 |
| `..`、绝对路径、NUL、反斜杠、`.melo-` 内部路径、符号链接/悬空链接 | 拒绝访问；根目录不能删除或移动；列表过滤内部项目和链接 |
| 带跨源 Origin 的修改请求 | 在读取正文前拒绝；普通 IP 地址 GET/HEAD 可直接访问 |

目录删除会包含隐藏文件；内部 `.melo-` 恢复目录不通过普通网页接口开放。多文件合并不是断电原子事务，强制结束 App 可能保留 `.melo-move-backup-*` 和 `recovery.json`；此时不要手动清理，先核对相对路径清单和正式文件。

## 大文件、中断与恢复

| 场景 | 预期结果 |
| --- | --- |
| 上传上述分片边界大小 | 每片最多 524,288,000 字节，最后一片取剩余大小；不得把整片载入内存 |
| 传输到一半断网 | 已确认偏移保留；未完成的当前片最多重传一片；正式名称不提前出现 |
| 网页刷新/关闭后重开 | 重新选择同一个文件，读取保存的上传会话，从服务端 `nextOffset` 继续 |
| 恢复时选择不同文件 | 抽样指纹不匹配时不继续原会话；不能把抽样指纹称为完整文件 SHA-256 校验 |
| 手机切后台或手动锁屏 | listener/现有连接停止；临时文件保留；不宣称后台可以继续完整传输 |
| 返回前台且网络地址未变 | 自动恢复此前开启的服务，优先复用端口；浏览器直接重试，并使用原 resumeToken 继续上传 |
| IP/端口改变或 App 重启 | 直接打开当前地址；origin 改变时使用网页恢复记录导出/导入，再重新选择文件并使用原 resumeToken 恢复 |
| 恢复请求缺失或使用错误的 resumeToken | 拒绝访问该上传会话，不追加数据或提交文件 |
| 分片写入后进度未保存即结束进程 | 重新启动时裁掉未确认尾部，从最后已确认偏移重传 |
| 完成响应丢失、重复 complete | 可读取完成收据，不重复覆盖目标 |
| 上传中改动原目标 | 最终提交拒绝覆盖已变化目标，旧文件不被静默替换 |
| 空间不足、写失败 | 返回明确错误，正式目标保持完整；临时数据是否可继续以会话状态为准 |
| 10 / 40 GiB 完成上传 | 正式文件大小与 SHA-256 和原文件一致；记录总耗时、平均速率、峰值内存和峰值磁盘占用 |
| 下载 10 / 40 GiB 并中断后续传 | 确认浏览器实际发出 `Range`，服务返回 `206`/`Content-Range`；最终 SHA-256 一致 |
| 含多个大文件的目录选择「下载全部」 | 前一文件响应发送结束后才启动下一文件；重复点击不重复创建队列；浏览器拦截下载、断网或发送失败时暂停并提示 |

上传中的数据位于 `.melo-transfer-temp/.../payload.melo-upload.part`，不是正式游戏文件；只有完整提交后才产生正式文件名。下载临时名称由浏览器管理，例如 `.crdownload` 或 `.part`，普通局域网 HTTP 网页不能强制所有浏览器都使用 `.melo-download.part`。关闭网页后能否恢复原生下载，还取决于浏览器下载器；服务支持 Range 不等于所有浏览器自动恢复。

## 防熄屏与浏览器边界

- 服务在前台运行期间持有常亮 lease，覆盖上传请求体读取、分片落盘及下载响应发送。即使网页暂时没有请求也保持常亮；传输完成后通过菜单或地址页停止服务。
- 连续等待超过系统自动锁屏时间，确认上传、下载均不中断。停止服务后检查恢复启动服务前的防熄屏状态；原先因游戏而常亮时应保持原值。
- 后台旧 lease 失效，回来后新服务不会被旧连接的释放动作解除常亮。手动锁屏和切后台仍会暂停服务。
- 文件夹下载是递归清单加逐文件原始下载，不打 ZIP。浏览器可能要求允许多文件下载，不能保证自动保留本地子目录、空目录和重复同名文件的目录层级。
- 批量队列的 `sent` 只表示服务端响应发送完毕；最终文件是否已写入本地磁盘，以浏览器下载器为准。网页关闭后不会自动继续启动尚未开始的队列项。
- 目录上传依赖 `webkitRelativePath`。普通选择器不会返回空目录，空目录通过网页「新建文件夹」补建。
