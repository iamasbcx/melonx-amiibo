# 预编译与缓存说明

MeloNX 当前可以跨启动复用两类缓存，但它们解决的问题不同：

- **Shader Cache** 保存游戏运行时实际遇到的 guest shader 以及当前图形后端生成的 host shader。启动时会在首帧前加载并校验已有缓存，后续运行可减少重复的着色器翻译和管线创建。
- **PTC（Profiled Persistent Translation Cache）** 是传统 `Jit` 后端的 CPU 翻译缓存。它会保存经过校验的翻译结果和调用资料，启动时按需恢复并预编译历史热点函数。

iOS arm64 和 Apple Silicon 的 HostMapped 路径默认使用 `LightningJit`。该后端目前只保留进程内可执行代码缓存，`LoadDiskCache` 返回空实现，因此不会跨启动复用 CPU 翻译结果。不能直接把进程中的 RX/RW 指针写入磁盘：下次启动时地址、调用桩、内存映射和 W^X 权限都会变化。

着色器也不能在完全没有运行游戏的情况下从 ROM 静态预编译完整集合。着色器依赖运行时 GPU 状态、纹理和管线组合；首次遇到的新组合仍可能触发即时编译。Vulkan 的异步编译可以把部分工作移到后台，但被当前帧立即需要的管线仍会提升为高优先级并等待完成。

推荐设置和使用流程：

1. 保持游戏的 **Shader Cache** 开启。新安装现在默认开启，已有配置中的显式开关保持不变。
2. 首次运行让游戏正常进入常用场景并游玩一段时间，使缓存覆盖常见效果；退出时缓存由后台写入。
3. 后续启动会在加载页恢复已收集缓存。可按游戏单独开启 **Async Shader Compilation (EXPERIMENTAL)**，以减少运行中等待，但出现图形异常时应关闭该选项。
4. 更换图形后端、GPU 驱动或核心代码后，旧 host cache 可能因校验不匹配而重建，这是为避免错误机器码被复用。
5. 删除 Shader Cache 会清除该游戏的已收集结果，下一次运行需要重新建立。

因此，当前最安全有效的优化是默认启用 Shader Cache，并保留异步编译为可选项。要给 `LightningJit` 增加 CPU 跨启动预编译，需要另行设计带版本、指令哈希、重定位和失效处理的持久化格式，不能复用现有的进程内映射。
